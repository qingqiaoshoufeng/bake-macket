# 商家后台固定列表工作区与订单供货清单设计

## 1. 背景

商家后台当前采用自然文档流：`AdminLayout` 仅保证最小视口高度，列表页的标题、筛选区、表格和分页共同撑高页面。数据较多时，滚动条属于整个浏览器页面；数据较少时，表格又不会填满剩余可视区域。结果是标题、筛选条件和分页会随页面滚动离开视口，PC 后台的操作效率较低。

订单管理当前只有“一个订单一行”的服务端分页列表。订单商品只能逐单打开详情查看，无法按 SKU 汇总尚需供货的数量，也没有 Excel 导出能力。运营人员难以快速回答“当前需要准备多少个某规格商品”以及“这些数量来自哪些订单”。

本设计在不改变订单状态机、下单扣库存规则和历史订单快照不可变原则的前提下，提供：

1. 所有后台列表页统一使用固定视口工作区，浏览器外层不滚动，表格数据区在剩余可视区域内滚动。
2. 订单管理支持“订单模式”和“SKU 供货模式”。
3. SKU 供货模式按稳定 SKU 快照 ID 汇总 `NEW`、`PROCESSING` 订单的需供货数量，并可展开追溯订单商品明细。
4. 两种模式均可按全部已应用筛选结果导出 Excel。

## 2. 范围

### 2.1 固定列表工作区

以下后台列表页统一启用固定工作区：

- 分类管理 `/categories`
- 商品管理 `/products`
- Banner 管理 `/banners`
- 订单管理 `/orders`
- 会员卡配置 `/membership-cards`
- 购卡记录 `/membership-purchases`

Dashboard、登录页、404 页、商品编辑页和会员卡编辑页等非列表页继续使用自然文档滚动。不得为了列表页关闭全站 `body` 滚动，从而裁切长表单或破坏 Element Plus Dialog/Drawer 的滚动锁。

### 2.2 订单工作台

订单页面提供两个互斥模式：

- **订单模式**：面向逐单查询、处理和状态流转。
- **SKU 供货模式**：面向按商品规格汇总需供货数量，并追溯构成该数量的订单。

两种模式复用统一的非状态筛选语义，但拥有独立页码和独立状态字段。切换模式时保留兼容的非状态筛选条件；订单模式继续使用单值 `status`，SKU 供货模式使用多值 `supplyStatuses`，首次进入时默认且显式应用 `[NEW, PROCESSING]`。

## 3. 关键业务口径

### 3.1 “需供货数量”

SKU 供货模式首版只允许以下运营状态范围：

- `NEW`
- `PROCESSING`
- `NEW + PROCESSING`

`supplyStatuses` 是非空数组，只允许 `NEW`、`PROCESSING`，去重后最多两个值；默认值为 `[NEW, PROCESSING]`。未传、空数组、包含 `COMPLETED/CANCELLED` 或其他值均返回 400，不用“未传状态”表达默认范围。需供货数量等于当前已应用筛选结果中，各 SKU 对应订单项 `quantity` 的总和。已完成和已取消订单不进入供货模式，避免把历史销量或取消数量混入当前备货任务。

汇总同时展示：

- 涉及订单数；
- 待处理数量；
- 处理中数量。

### 3.2 库存字段的语义

现有 `sku.stock` 在订单创建事务中已经按订单数量原子扣减，表示下单后的剩余可售库存。它不是“尚未分配给待供货订单的库存”。因此不得计算：

```text
缺口 = 需供货数量 - sku.stock
```

该计算会把订单需求重复扣减并误导运营。

首版以“需供货数量”为唯一供货决策指标。页面可展示“剩余可售库存（参考）”，但必须：

- 明确标注“参考”；
- 不计算供货缺口；
- 不用颜色或告警暗示该库存可以抵扣当前供货任务；
- Excel 中采用同样名称和说明。

页面查询返回的剩余可售库存是查询时的参考快照；Excel 为保证两个 Sheet 一致，在导出事务开始时读取一次并复用于工作簿，不承诺与下载完成时的实时库存相同。

未来若需要真实供货缺口，必须另行设计“已备货库存/可履约库存”及其出入库规则，不复用当前可售库存。

### 3.3 商品行金额

订单项的 `linePayableCents` 是会员折扣后的行金额，不包含订单级消费金分摊。消费金当前没有按订单项持久化分摊结果。因此：

- 商品明细中将 `linePayableCents` 展示为“会员折后金额”；
- 不展示或导出虚构的“商品最终实付金额”；
- SKU 汇总不按商品行汇总订单级消费金；
- 供货 Excel 的商品明细首版不重复写入订单级消费金，避免用户跨行求和得到错误结果。

### 3.4 履约时间

当前配送订单没有结构化的承诺送达时间，自提时间也是文本快照。系统不得从下单时间、地址文本或不可比较的自提文本推导“最早供货截止时间”。

SKU 汇总展示“最早下单时间”；具体自提时间或配送地址在展开的订单明细及 Excel 明细中展示。未来如需按供货截止时间排序，应先新增结构化履约时间契约和订单快照字段。

## 4. 固定列表工作区设计

### 4.1 滚动责任

列表页使用以下纵向结构：

```text
AdminLayout（固定为 100dvh，overflow hidden）
└── Main
    ├── Topbar（固定内容高度）
    └── Canvas（minmax(0, 1fr)，overflow hidden）
        └── AdminPage workspace
            ├── PageHeader（auto）
            ├── Alert（可选，auto）
            └── AdminDataPanel fill（minmax(0, 1fr)）
                ├── Toolbar / Filters（auto）
                ├── Table Data（minmax(0, 1fr)）
                └── Pagination（auto）
```

约束：

- 列表工作区内不产生 `body/document` 纵向滚动。
- 页面标题、模式切换、筛选区和分页始终留在工作区内。
- 表格数据区占满剩余高度；数据多时只在该区域纵向滚动。
- 空状态和 loading 状态同样填满表格数据区，不使面板塌缩。
- 不使用硬编码 `calc(100vh - 68px - ...)`；高度通过 Grid/Flex 的 `minmax(0, 1fr)`、`min-height: 0` 和明确的父级高度逐层传递。
- 低高度视口下允许表格区域缩小；更多筛选仍可折叠。不得退化成整页滚动。

### 4.2 页面模式边界

路由元信息区分：

```ts
type AdminLayoutMode = 'workspace' | 'document';
```

- 六个列表路由使用 `workspace`。
- 编辑页、Dashboard 和其他长内容页面使用 `document`。
- `AdminLayout` 只在 `workspace` 模式固定视口和裁切外层溢出。
- `AdminPage` 提供对应的 workspace 布局能力。
- `AdminDataPanel` 提供填充剩余高度的能力，但不改变普通文档模式下的自然高度。

### 4.3 表格滚动

工作区表格以 Element Plus 表格内部 body wrapper 作为唯一纵向和横向滚动区域：

- `AdminDataPanel` 负责尺寸分配和裁切，不再在工作区模式额外包第二层横向滚动。
- `ElTable` 接收可用高度并让表头固定、表体滚动。
- 固定在右侧的操作列继续由 Element Plus 管理。
- 宽表格保留受控 `min-width`；横向滚动只出现一次。
- 普通文档模式或非 Element Plus 内容仍可复用现有横向滚动工具。

该规则对 `2026-07-26-admin-list-filters-responsive-design.md` 中“`AdminDataPanel` 保持唯一横向滚动容器”的约定作针对性更新：固定工作区中的 Element Plus 表格改由表格内部滚动层统一承担双轴滚动，以避免外层与表格内部形成双滚动。

### 4.4 响应式边界

后台仍以 PC 为主要使用环境：

- 验收宽度为 1024px、1440px、1920px。
- 小于 1024px 继续显示桌面建议提示，不新增移动端侧栏。
- 提示条出现后仍通过布局轨道自动扣除高度，不使用固定像素减法。
- 抽屉、对话框和下拉层继续使用 Element Plus Teleport，不被工作区 `overflow` 裁切。

## 5. 订单模式

### 5.1 筛选

保留现有订单筛选：

基础筛选：

- 订单号；
- 联系人或手机号；
- 订单状态；
- 履约方式。

更多筛选：

- 用户 ID；
- 商品或 SKU 关键词；
- 是否使用会员；
- 是否使用消费金；
- 是否有备注；
- 应付金额范围；
- 下单时间范围。

查询仍采用“筛选草稿”和“已应用筛选”分离：只有点击查询后才更新列表和导出口径；分页、详情和导出不得读取尚未提交的草稿。

### 5.2 表格

订单表格展示：

- 订单号；
- 联系人 / 手机号；
- 履约方式；
- 商品种类数；
- 商品总件数；
- 商品原价；
- 会员优惠；
- 消费金抵扣；
- 应付金额；
- 状态；
- 下单时间；
- 操作：查看详情和合法状态流转。

`itemLineCount` 表示订单项行数，`totalQuantity` 表示所有订单项数量之和。金额必须使用整数分契约，并通过现有格式化函数显示为元。

## 6. SKU 供货模式

### 6.1 汇总键

新订单项快照增加：

- `productId`
- `skuId`

它们记录下单时来源实体的 ID，仅用于历史追溯和稳定聚合：

- 数据库列使用可空 `BIGINT UNSIGNED`，以兼容历史订单；
- 不建立会阻止商品/SKU 删除的外键；
- 新订单写入时应用层必须提供两个 ID；
- 商品名称、SKU 名、规格、图片、价格等现有不可变快照继续保留，展示不依赖实时商品。

已知 SKU 使用 `skuId` 聚合。`productId` 用于追溯与导出，不作为 SKU 汇总的唯一键。

### 6.2 历史订单回填与兜底

迁移对历史订单项执行保守回填：

1. 将订单项的商品名、SKU 名和规格属性规范化。
2. 在现有商品/SKU 数据中查找完全匹配候选。
3. 只有恰好一个候选时回填 `productId/skuId`。
4. 无候选或多候选时保持为空，不猜测 ID。

无法回填的历史订单项采用规范化的“商品名 + SKU 名 + 排序后的规格键值”作为兜底分组输入，并生成稳定的 opaque `groupKey`。这类汇总行必须标记“历史匹配”，且实时剩余可售库存显示为不可用，避免把同名数据伪装成可靠 SKU。

回填和兜底均不得修改订单项的名称、规格、价格、数量或金额快照。

### 6.3 汇总表

每个汇总行包含：

- opaque `groupKey`；
- `productId`、`skuId`，历史兜底时可空；
- 商品名；
- SKU 名；
- 规格属性；
- 需供货数量；
- 涉及订单数；
- 待处理数量；
- 处理中数量；
- 剩余可售库存（参考），历史兜底时为空；
- 最早下单时间；
- 数据匹配状态：`SKU_ID` 或 `LEGACY_FALLBACK`。

默认排序：

1. 需供货数量降序；
2. 最早下单时间升序；
3. `groupKey` 升序作为稳定次排序。

汇总分页在数据库执行，不将全部订单项加载到 Node 后再分页。

### 6.4 展开明细

用户展开某一汇总行时，以 `groupKey + 当前已应用筛选` 懒加载该组订单商品明细。每行展示：

- 订单号；
- 订单状态；
- 履约方式；
- 联系人 / 手机号；
- 自提时间或配送地址快照；
- 该 SKU 数量；
- 买家备注；
- 下单时间。

展开明细默认按：

1. 下单时间升序；
2. 订单 ID 升序；
3. 订单项 ID 升序。

单个分组的明细请求失败只影响该展开区域，保留汇总主表并提供重试。模式切换或筛选变化后清理已展开缓存，避免展示与主表条件不一致的旧明细。

### 6.5 商品关键词语义

订单模式中，商品关键词语义保持为：只要订单内任意商品名或 SKU 名匹配，订单就进入结果。

SKU 供货模式中，商品关键词只保留自身商品名或 SKU 名匹配的汇总行与明细行。同订单中其他未匹配商品不得混入供货数量。

## 7. 共享契约与 API

### 7.1 共享契约

在 `@bake-mall/contracts` 中定义并导出：

- `AdminOrderFilterQuery`
- `AdminOrderListQuery`
- `AdminOrderSupplyQuery`
- `AdminOrderSupplyDetailQuery`
- `AdminOrderExportQuery`
- `AdminOrderExportView`
- `AdminOrderListItem` 扩展字段
- `AdminOrderSupplyItem`
- `AdminOrderSupplyDetailItem`
- `AdminOrderSupplyMatchType`

分页查询与纯筛选分离：

```ts
type AdminOrderListQuery = AdminOrderFilterQuery &
  AdminPageQuery & {
    status?: OrderStatus;
  };

type AdminOrderSupplyQuery = AdminOrderFilterQuery &
  AdminPageQuery & {
    supplyStatuses: readonly SupplyOrderStatus[];
  };

type AdminOrderExportQuery =
  | (AdminOrderFilterQuery & {
      view: AdminOrderExportView.ORDER;
      status?: OrderStatus;
    })
  | (AdminOrderFilterQuery & {
      view: AdminOrderExportView.SUPPLY;
      supplyStatuses: readonly SupplyOrderStatus[];
    });
```

`AdminOrderFilterQuery` 只放两种模式共享的非分页、非状态条件。订单模式可使用全部订单状态；SKU 供货查询和导出必须显式传入非空 `supplyStatuses`，且只接受 `NEW`、`PROCESSING` 或二者组合。

### 7.2 API 端点

保留：

```text
GET   /api/v1/admin/orders
GET   /api/v1/admin/orders/:id
PATCH /api/v1/admin/orders/:id/status
```

新增：

```text
GET /api/v1/admin/orders/supply
GET /api/v1/admin/orders/supply-items
GET /api/v1/admin/orders/export?view=ORDER|SUPPLY
```

路由声明必须避免 `:id` 抢先匹配 `supply`、`supply-items` 和 `export`。

- `/orders/supply` 返回服务端分页的 SKU 汇总。
- `/orders/supply-items` 通过 opaque `groupKey` 和当前筛选返回分组明细。
- `/orders/export` 忽略分页，按 view 生成对应 Excel。

### 7.3 统一筛选构造器

订单列表、SKU 汇总、展开明细和导出必须复用同一套服务端筛选构造逻辑，统一：

- 文本 trim 与 SQL LIKE 转义；
- 状态、履约方式和布尔过滤；
- 金额整数分范围；
- 时间范围 `from <= createdAt < before`；
- 商品关键词在两种模式下的明确差异；
- 稳定排序。

不得为 Excel 复制一套容易漂移的筛选 SQL。

## 8. Excel 导出

### 8.1 通用行为

- 导出当前模式下全部已应用筛选结果，忽略当前分页。
- 导出期间按钮进入 loading 并禁用重复点击，列表仍可浏览。
- API 返回 XLSX 二进制、正确 MIME 类型与 UTF-8 `Content-Disposition` 文件名。
- Admin 全局 HTTP 客户端增加带鉴权、401 处理和统一错误解析的 Blob 下载能力；页面 API 层不自行使用裸 `fetch`。
- 文件名不包含联系人、手机号等个人信息。
- 推荐文件名：`订单列表_YYYYMMDD_HHmmss.xlsx`、`SKU供货清单_YYYYMMDD_HHmmss.xlsx`。

### 8.2 订单模式工作簿

包含一个 Sheet：“订单列表”。每个订单一行，字段包括：

- 订单号；
- 用户 ID；
- 联系人、手机号；
- 状态、履约方式；
- 商品种类数、商品总件数；
- 商品原价、会员优惠、消费金抵扣、应付金额；
- 自提时间或配送地址快照；
- 会员 code、名称、折扣快照；
- 买家备注；
- 下单时间、更新时间。

金额单元格写入数值元并设置 Excel 金额格式，不写入带 `¥` 的字符串，便于用户求和。订单号、手机号和各类 ID 作为文本写入，避免科学计数法和前导零丢失。

### 8.3 SKU 供货工作簿

包含两个 Sheet。

“SKU 供货汇总”：

- 商品 ID、SKU ID；
- 商品名、SKU 名、规格；
- 需供货数量、涉及订单数；
- 待处理数量、处理中数量；
- 剩余可售库存（参考）；
- 最早下单时间；
- 数据匹配状态。

“订单商品明细”：

- 订单号、订单状态、履约方式；
- 联系人、手机号；
- 自提时间或配送地址快照；
- 商品 ID、SKU ID；
- 商品名、SKU 名、规格；
- 本单数量、成交单价、行原价、行会员优惠、会员折后金额；
- 买家备注、下单时间。

明细不导出虚构的商品最终实付，也不重复订单级消费金。

### 8.4 数据量上限与一致性

同步导出最多允许 50,000 个数据行：

- 订单模式按订单行计数；
- SKU 供货模式按“订单商品明细”行数计数，汇总 Sheet 不重复计入上限；
- 超限时不得截断文件，返回明确 `EXPORT_TOO_LARGE` 错误，提示缩小时间范围或筛选条件；
- Excel 内容在同一数据库一致性视图内读取；SKU 汇总 Sheet 由同批明细数据派生，避免两个 Sheet 数量不一致。

未来若数据量增长，可把相同导出查询契约接入异步任务和 MinIO 下载，不改变页面筛选口径。

### 8.5 Excel 安全

所有来自用户或运营输入的文本字段必须防止公式注入：

- 以 `=`, `+`, `-`, `@` 开头的文本按纯文本写入并进行安全转义；
- 不把用户文本组装成 Excel 公式；
- 限制单元格文本长度并保持错误可观测；
- HTML 备注或富文本不得原样作为可执行内容写入。

导出包含手机号、地址等个人信息，只允许 `mall-admin` audience 访问。成功导出写入审计日志，记录导出模式、规范化筛选摘要、行数和时间，不在审计摘要中复制完整手机号或地址。

## 9. Admin 前端模块边界

订单页面继续遵循 feature 模块拆分：

```text
views/orders/
├── api/          # 订单、供货汇总、明细和导出端点
├── components/   # 模式切换、订单表、供货表、展开明细
├── config/       # 两种表格列、分页与导出文案
├── hooks/        # 订单列表、供货列表、明细缓存、导出流程
├── mock/         # 两种模式测试数据
├── type/         # 仅视图层状态，不重复共享 DTO
└── OrdersView.vue
```

约束：

- 业务查询、模式状态和导出副作用放入 hooks；
- components 不发请求；
- API 层只组合全局客户端，不转换 DTO；
- 跨 API/Admin 的数据结构只来自 `@bake-mall/contracts`；
- 数组聚合、映射与排序保持不可变和 ES6 函数式风格；
- 清理当前订单域内不一致的旧 API 类型入口，避免继续维护两套返回类型。

模式状态：

- 两个模式维护独立页码；
- 兼容筛选在切换时保留；
- SKU 供货状态默认且仅允许 `NEW`、`PROCESSING` 的一个或两个；
- 切换模式不自动发起 Excel 导出；
- 快速重复请求使用 request sequence 或取消机制，旧响应不得覆盖新状态。

## 10. 错误与状态处理

- 列表失败：保留现有数据和已应用筛选，显示页面级错误及重试。
- 空结果：区分“暂无订单”和“当前筛选无结果”。
- 汇总明细失败：只影响对应展开行，可单独重试。
- 导出失败：结束 loading，保留页面状态，显示统一 `ApiError` 信息。
- 导出超限：显示上限和缩小筛选建议，不自动降级成截断文件。
- 历史兜底：不丢弃数据，在页面和 Excel 中明确标记。
- 下载文件名解析失败：使用前端安全默认文件名。
- 401：沿用全局 Admin 退出登录流程。
- 生成 Excel 或审计记录失败不得返回伪成功文件；错误应进入服务端日志。

## 11. 测试与验收

### 11.1 共享契约

类型级和运行时测试覆盖：

- 两种列表查询、供货明细查询和导出查询；
- SKU 供货状态只允许 `NEW`、`PROCESSING`；
- 汇总行与明细行的必填字段；
- 非法 view、金额、时间、分页和缺失字段。

### 11.2 数据库迁移与订单创建

覆盖：

- `order_items.product_id/sku_id` 类型、可空性和索引；
- 新订单始终保存来源 ID；
- 唯一匹配的历史数据被回填；
- 无匹配或多匹配数据保持为空；
- 回填不修改既有快照；
- migration `up/down`；
- 订单创建原子扣库存和幂等行为不回归。

### 11.3 API 单元与 MySQL e2e

覆盖：

- SKU 供货默认 `NEW + PROCESSING`；
- 只选 `NEW` 或只选 `PROCESSING`；
- 所有既有筛选在订单、供货汇总、展开明细和导出之间一致；
- 订单模式商品关键词使用订单级 `EXISTS`；
- 供货模式商品关键词只匹配当前 SKU 行；
- SKU 数量、订单数和状态拆分聚合正确；
- 同名但不同 `skuId` 不误合并；
- 历史兜底稳定且不丢数据；
- 汇总分页与稳定排序；
- 展开明细顺序；
- 订单列表商品种类数和总件数；
- 50,000 行成功、50,001 行返回 `EXPORT_TOO_LARGE`；
- XLSX MIME、文件名、Sheet 数量、字段类型和金额格式；
- 两个供货 Sheet 数量一致；
- 公式注入文本不会成为公式；
- Admin audience 与审计记录。

### 11.4 Admin 单元测试

覆盖：

- 订单/SKU 供货模式切换；
- 独立页码和兼容筛选保留；
- 供货状态默认值及允许范围；
- 筛选草稿与已应用条件；
- 展开明细懒加载、缓存失效和重试；
- Blob 下载、`Content-Disposition` 文件名、安全默认名；
- 导出 loading、防重复点击和错误提示；
- 六个列表路由使用 workspace，编辑页使用 document；
- 空状态和 loading 填满表格区域。

### 11.5 真实浏览器验收

使用真实 API 和浏览器在 1024px、1440px、1920px 宽度检查：

- 六个列表页不产生 body 纵向滚动；
- 页面标题、筛选区和分页始终可访问；
- 少量、大量、空数据均填满数据面板；
- 表格只有一个纵向和一个横向滚动层；
- 固定操作列、表头、抽屉和对话框正常；
- 更多筛选展开和错误 Alert 不破坏高度链；
- 编辑页和登录页仍可自然滚动；
- 两种订单模式切换与展开明细可用；
- 实际下载并打开两类 Excel，核对行数、Sheet、金额、ID/手机号文本格式和中文文件名。

## 12. 非目标

- 不改变订单状态机 `NEW → PROCESSING → {COMPLETED | CANCELLED}`。
- 不改变下单原子扣库存和取消不回补库存规则。
- 不建设备货库存、仓库、采购单、出入库流水或真实库存缺口模型。
- 不新增配送承诺时间或供货截止时间模型。
- 不把订单级消费金强行分摊到商品行。
- 不建设异步导出任务、消息队列或报表中心。
- 不新增移动端后台导航。
- 不修改 H5 或小程序的订单展示。
- 不进行与列表工作区、订单供货汇总和 Excel 导出无关的视觉重构。

## 13. 验收摘要

满足以下条件才视为完成：

1. 六个后台列表页外层固定、表格填满剩余区域并内部滚动，非列表页滚动不回归。
2. 订单模式继续支持完整筛选、分页、详情和状态处理。
3. SKU 供货模式准确汇总 `NEW/PROCESSING` 订单数量，并可追溯构成明细。
4. 新订单按 SKU ID 稳定聚合，历史订单无法可靠回填时不丢失且明确标记。
5. 两种模式均按全部已应用筛选结果生成可打开、可求和且安全的 Excel。
6. 供货口径不使用剩余可售库存计算虚假缺口，不生成虚假的商品最终实付金额或供货截止时间。
