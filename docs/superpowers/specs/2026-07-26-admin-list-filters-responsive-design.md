# 商家后台列表筛选与宽度自适配设计

## 1. 背景与目标

商家后台现有 6 个列表页面的查询体验不一致：分类、商品和 Banner 没有过滤能力；订单与购卡记录各自维护相似但不同的查询网格；会员卡又采用第三套工具栏布局。查询表单依赖 viewport 断点，在扣除侧栏和页面留白后容易出现控件挤压、日期框过窄、按钮排列混乱等问题。

本次改造目标：

1. 为所有列表页补齐运营常用过滤项，并在服务端执行过滤和分页。
2. 统一查询区的视觉、间距、按钮与交互。
3. 查询字段根据容器可用宽度自动排列和换行，不为不同 PC 分辨率维护页面级固定布局。
4. 修正列表横向滚动、操作列一致性和已发现的订单金额展示错误。

涉及页面：

- 分类管理 `/categories`
- 商品管理 `/products`
- Banner 管理 `/banners`
- 订单管理 `/orders`
- 会员卡配置 `/membership-cards`
- 购卡记录 `/membership-purchases`

## 2. 查询区设计

### 2.1 共用边界

新增共用 `AdminFilterPanel`，只负责查询区的视觉和交互骨架：

- 基础字段区域；
- “更多筛选”折叠区域；
- 查询、重置和展开/收起操作区；
- 当前已生效筛选数量；
- loading 状态。

各页面继续维护自己的字段模板、过滤状态、默认值与请求转换，不建设由配置动态生成所有 Element Plus 控件的表单引擎。

所有查询区统一放入 `AdminDataPanel` 的 `toolbar` slot。

### 2.2 宽度自适配

字段区域采用容器宽度驱动的 CSS Grid：

```css
grid-template-columns: repeat(auto-fit, minmax(min(100%, 220px), 1fr));
```

约束：

- 单字段最小目标宽度约 220px；容器更窄时允许占满一行。
- `ElInput`、`ElSelect`、`ElDatePicker` 和数字区间控件宽度统一为 100%。
- 日期范围和组合区间字段可通过 span 类获得更宽空间；空间不足时自动占满一行。
- 操作区与字段区分离，按钮不参与字段列宽计算。
- 不根据 `1920px`、`1440px`、`1280px` 等 viewport 编写多套页面级网格。
- 默认显示高频过滤项；低频项放入“更多筛选”，展开后使用同一自适应网格。

### 2.3 交互

- 点击“查询”应用草稿条件、回到第 1 页并请求列表。
- Enter 在非多行输入控件中触发查询。
- 点击“重置”恢复默认条件、收起更多筛选、回到第 1 页并立即请求。
- 修改 pageSize 后回到第 1 页。
- 列表请求只使用已应用条件，编辑未提交的草稿条件不影响当前结果。
- “更多筛选”显示其中已生效的条件数量。

## 3. 各页面过滤项

### 3.1 分类

基础筛选：

- 分类名称关键字；
- 启用状态。

更多筛选：

- 是否有图片；
- 是否有关联商品；
- 创建时间范围。

### 3.2 商品

基础筛选：

- 商品名称关键字；
- 分类；
- 上架状态。

更多筛选：

- SKU 可用状态；
- 库存状态：有库存、低库存、缺货；
- 是否有主图；
- SKU 售价区间；
- 创建时间范围。

低库存阈值由查询参数提供，选择“低库存”时使用统一默认阈值 10。

### 3.3 Banner

基础筛选：

- 标题关键字；
- 上架状态；
- 跳转类型。

更多筛选：

- 跳转目标；
- 目标是否仍有效；
- 创建时间范围。

跳转目标选择器随跳转类型展示分类或商品选项。

### 3.4 订单

基础筛选：

- 订单号；
- 联系人或手机号关键字；
- 订单状态；
- 履约方式。

更多筛选：

- 用户 ID；
- 商品或 SKU 关键字；
- 是否使用会员；
- 是否使用消费金；
- 是否有顾客备注；
- 应付金额区间；
- 下单时间范围。

列表响应必须返回 `membershipDiscountCents`、`creditAppliedCents` 和 `payableTotalCents`，不得以商品原价代替应付金额。

### 3.5 会员卡

基础筛选：

- 名称或 code 关键字；
- 上架状态；
- 等级 rank。

更多筛选：

- 价格区间；
- 折扣区间；
- 已售/未售；
- 卡面主题；
- 有效期范围；
- 更新时间范围。

### 3.6 购卡记录

基础筛选：

- 购卡单号；
- 用户手机号；
- 会员等级；
- 履约状态。

更多筛选：

- 支付状态；
- 实付金额区间；
- 是否允许作废；
- 创建时间范围；
- 支付时间范围；
- 作废时间范围。

会员等级使用可读的名称/code 选择器，不要求运营人员手工输入 level ID。

## 4. 契约与 API

### 4.1 共享契约

在 `@bake-mall/contracts` 中定义后台列表查询、布尔/范围过滤枚举和统一分页响应。跨 API 与 Admin 的 DTO 不在应用内重复定义。

统一分页响应：

```ts
interface PaginatedView<T> {
  items: T[];
  total: number;
  page: number;
  pageSize: number;
}
```

各查询均包含 `page`、`pageSize`，默认每页 20 条，允许 10、20、50、100。

### 4.2 查询语义

- 所有文本关键字先 trim。
- SQL `LIKE` 查询转义 `%`、`_` 和转义字符本身。
- 枚举与布尔条件精确匹配。
- 金额使用整数分，不接受浮点数。
- 最小值和最大值均为包含边界。
- 时间范围统一为 `from <= value < before`。
- 默认业务排序保持现状，并追加 `id` 作为稳定次排序。
- 过滤和分页在数据库执行，不先加载全表再在 Node 中过滤。

### 4.3 性能

- 分类、商品和 Banner 从全量返回改为服务端分页。
- 商品列表批量聚合 SKU 状态、最低价格和库存，消除逐商品查询 SKU 的 N+1。
- 会员卡的已售数量使用聚合查询。
- 购卡记录的过滤和分页下推数据库；详情与可作废判断继续按当前业务规则计算。

## 5. 表格和 PC 页面适配

- `AdminDataPanel` 保持唯一横向滚动容器。
- 删除会员卡表格内部的第二层横向滚动。
- 降低会员卡表格不必要的 `1500px` 最小宽度，压缩卡面预览与操作列；字段过多时允许单一横向滚动。
- 分类和商品操作列固定在右侧，与其他列表一致。
- 查询区宽度自适应，不靠 viewport 断点猜测扣除侧栏后的空间。
- 修正购卡查询提示文字使用不存在的 CSS 变量。
- 本次不新增移动端后台导航；后台仍以 PC 为主要使用环境。

## 6. 错误与状态处理

- 查询失败保留当前已应用条件和现有列表，显示明确错误提示。
- 无结果时区分“尚无数据”和“当前筛选无结果”。
- 页面切换或快速重复查询时，旧请求结果不得覆盖较新的查询结果。
- 请求参数验证失败沿用统一 `ApiError` 展示。

## 7. 测试与验收

### 7.1 共享契约

- 查询 DTO 合法与非法形态的类型级断言。
- 分页响应结构测试。

### 7.2 API

每个列表接口至少覆盖：

- 单条件过滤；
- 组合过滤；
- 边界值；
- 时间排他上界；
- 稳定分页；
- 无结果；
- 非法参数返回 400。

订单额外覆盖会员折扣/消费金后的应付金额；商品覆盖库存与价格聚合筛选。

### 7.3 Admin

- 查询参数转换；
- 查询、重置与页码复位；
- 更多筛选计数与折叠；
- 各页面基础/高级过滤字段；
- 请求竞态保护；
- 空状态和失败状态。

### 7.4 运行时验收

使用真实 API 和浏览器检查 6 个列表页：

- 查询控件随内容容器宽度自动排列；
- 不出现控件重叠、过窄或按钮挤入字段区；
- 更多筛选展开/收起正常；
- 查询、重置、分页与 pageSize 生效；
- 表格仅有一层横向滚动；
- 固定操作列可用；
- 订单应付金额正确。

## 8. 非目标

- 不重做后台整体视觉主题。
- 不新增移动端侧栏抽屉。
- 不改 C 端页面。
- 不改变订单状态机、库存、支付或会员权益规则。
- 不进行与列表筛选无关的表格渲染引擎重构。
