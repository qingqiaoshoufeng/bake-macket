# 默认四档会员等级设计

## 1. 目标与语义

系统预装银卡、金卡、钻石卡、黑卡四个可购买会员等级，首次迁移后全部上架并在 C 端会员中心展示。

“默认会员等级”仅指所有环境中的默认可购产品配置，不表示新用户自动获得会员。新用户仍保持 `currentMembership: null`，只有成功购卡后才创建会员记录、权益有效期和消费金发放记录。

## 2. 四档配置

| 等级   | code      | rank | sortOrder | 价格 | 赠送消费金 |   折扣 | 有效期 | 主题        | badge     |
| ------ | --------- | ---: | --------: | ---: | ---------: | -----: | -----: | ----------- | --------- |
| 银卡   | `SILVER`  |   10 |        10 |  ¥99 |        ¥10 | 9.5 折 | 365 天 | `PEARL`     | `SILVER`  |
| 金卡   | `GOLD`    |   20 |        20 | ¥199 |        ¥30 |   9 折 | 365 天 | `CHAMPAGNE` | `GOLD`    |
| 钻石卡 | `DIAMOND` |   30 |        30 | ¥399 |        ¥80 | 8.5 折 | 365 天 | `JADE`      | `DIAMOND` |
| 黑卡   | `BLACK`   |   40 |        40 | ¥699 |       ¥160 |   8 折 | 365 天 | `OBSIDIAN`  | `BLACK`   |

数据库值：

| code      | priceCents | grantCreditCents | discountBasisPoints | validDays |
| --------- | ---------: | ---------------: | ------------------: | --------: |
| `SILVER`  |       9900 |             1000 |                9500 |       365 |
| `GOLD`    |      19900 |             3000 |                9000 |       365 |
| `DIAMOND` |      39900 |             8000 |                8500 |       365 |
| `BLACK`   |      69900 |            16000 |                8000 |       365 |

四档均使用：

- `isActive = true`
- `version = 1`
- subtitle 和 description 使用简洁、面向顾客的中文文案
- rank 决定续费、升级和降购规则
- sortOrder 决定 API 和 Admin 默认显示顺序

## 3. 默认权益

权益仅作为展示型会员说明；真正自动执行的折扣和消费金仍由 `discountBasisPoints` 与 `grantCreditCents` 驱动。权益数组顺序就是 C 端展示顺序，`sortOrder` 与数组索引保持一致。

### 3.1 银卡

1. `全场商品 9.5 折`
   - 会员有效期内，参与折扣的烘焙商品享受 9.5 折。
2. `开卡赠送 ¥10 消费金`
   - 购卡成功后一次性发放，可用于商品订单抵扣。
3. `生日月专属祝福卡`
   - 生日月下单可备注领取门店手写祝福卡。

### 3.3 钻石卡

## 4. 落地方式

新增版本化数据迁移：

```text
apps/api/src/database/migrations/0007-default-membership-levels.ts
```

并在 `apps/api/src/database/data-source.ts` 中显式注册。

不使用以下方式：

- 不修改已执行的 `0005` 迁移；
- 不在 API 每次启动时执行 seed；
- 不依赖 Admin/H5 mock；
- 不通过未版本化的本地 SQL 导入作为正式实现。

## 5. up 行为与冲突规则

迁移在单个事务中处理四档配置。

对每一档：

1. 同时按稳定 code 与稳定 rank 查询已有记录。
2. code 和 rank 均未占用时，插入该档默认配置。
3. code 命中同一记录且 rank 一致时，视为该档已存在，不覆盖任何字段。
4. code 与 rank 分别命中不同记录时，迁移失败并回滚。
5. code 已存在但 rank 不一致，或 rank 已被其他 code 使用时，迁移失败并回滚。

迁移只补充缺失等级，不使用 `ON DUPLICATE KEY UPDATE`，避免覆盖商家已在 Admin 修改的价格、权益、主题、上下架状态和版本。

如果已有记录的 code/rank 与默认档位一致，但其他字段与默认值不同，保留已有配置并继续迁移。这代表该档已由商家配置，迁移不夺取配置所有权。

## 6. down 行为与回滚安全

回滚只处理稳定 code 为 `SILVER/GOLD/DIAMOND/BLACK` 的记录。

执行删除前：

1. 检查四档是否被 `membership_purchase_orders` 引用；
2. 检查是否被 `user_memberships` 引用；
3. 任意引用存在时，抛出明确错误并停止回滚；
4. 无引用时，在事务中删除四档。

迁移不尝试删除购卡单、会员记录、消费金或订单快照。

## 7. 跨端展示

### Admin

会员卡配置页按 `sortOrder ASC` 显示银、金、钻石、黑卡；管理员可以编辑全部业务字段或上下架。

### H5

无当前会员时，会员中心展示四档可购买等级。已有会员时沿用现有能力排序：当前等级优先，其次升级档位，再次降购档位；四档 rank 依次为 10、20、30、40，因此升级关系稳定。

不修改现有续费、升级、降购、消费金和折扣规则。

## 8. 测试

### 迁移单元测试

覆盖：

- 空表插入四档；
- 精确金额、折扣、主题、rank、sortOrder 和权益 JSON；
- 同 code/rank 记录存在时跳过且不覆盖；
- code/rank 冲突时失败并回滚；
- down 无引用时删除；
- down 遇到购卡或会员引用时拒绝。

### 真实 MySQL e2e

覆盖：

- 在应用 `0005`、`0006` 后执行 `0007`；
- 数据库约束和 JSON 均可执行；
- 重复执行迁移等价检查不会产生重复记录；
- 回滚安全检查有效。

### 运行时验收

- 运行迁移后 Admin API 返回四档；
- C 端会员概览返回四档上架等级；
- 顺序为银卡、金卡、钻石卡、黑卡；
- 新用户概览仍为 `currentMembership: null`；
- 购买后按对应价格、折扣、有效期和赠送消费金生成不可变快照。

## 9. 非目标

- 不给新用户自动发放银卡；
- 不新增免费会员等级；
- 不修改会员状态机或升级规则；
- 不实现生日礼、试吃活动、优先预订等权益的自动核销；
- 不修改 H5 卡面布局；
- 不覆盖商家已有会员等级配置。
