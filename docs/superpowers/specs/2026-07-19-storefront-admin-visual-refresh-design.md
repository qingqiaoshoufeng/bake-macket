# H5 与 Admin 全局视觉焕新设计规格

- **日期：** 2026-07-19
- **状态：** 已确认，待实施
- **范围：** `apps/h5-store` 与 `apps/admin-web` 的全局设计系统、布局骨架和全部现有业务页面
- **最高原则：** 优化视觉效果并保证业务流程通畅；视觉表达不得削弱可读性、触控可用性、表格效率、表单反馈或已验收业务行为

## 1. 背景与目标

当前两端已经具备商品、购物车、订单、Banner 和后台管理等核心流程，但视觉实现以页面局部样式为主，缺少统一的页面骨架与组件密度。实际运行中表现为：

- H5 页面最大宽度、水平留白、卡片半径、阴影、标题层级和固定底栏避让不一致；原生表单控件混入后视觉突兀。
- H5 同时使用 Banner、异形 hero、大衬线标题、暖棕占位和重阴影，元素竞争注意力，未形成清透的小清新气质。
- Admin 仅通过紫粉配色表达“轻二次元”，侧栏、顶部栏、页面标题、筛选、表格和表单缺少统一结构。
- Admin 各业务页自行绘制渐变标题和卡片，页面密度、边距与层级不一致，宽屏下内容容易松散。

本次目标：

1. 为 H5 建立“晨露烘焙”设计系统，统一清透、柔和、商品优先的移动商城体验。
2. 为 Admin 建立“店长小助手”设计系统，在保持后台效率的前提下形成明确的轻二次元品牌感。
3. 通过统一 token、页面壳和通用展示组件消除全站布局错乱，而不是逐页添加临时 CSS。
4. 保留全部已验收业务行为、API 边界、共享 DTO、状态机、表单校验和数据流。

## 2. 非目标

本次不包含：

- 修改 API、数据库、共享契约、订单状态机、库存或鉴权逻辑。
- 新增业务模块、促销能力、支付能力或小程序薄壳。
- 引入大型 UI 框架、第三方富文本编辑器或运行时主题切换。
- 使用装饰动画干扰表格、筛选、保存和状态更新。
- 为了视觉统一而删除错误、加载、禁用、空状态或确认提示。

## 3. 总体方案

采用“设计系统 + 页面骨架迁移”，不选择逐页修饰或整套业务重写。

实施顺序：

1. 建立两端视觉 token、全局 reset、字体层级、间距、圆角、阴影和响应式基线。
2. 建立 H5 页面壳、页面标题、区块卡片、状态展示与固定导航规范。
3. 建立 Admin 应用壳、统一页面头、工具栏/筛选卡、数据面板和表单分区规范。
4. 按核心流程迁移全部现有页面。
5. 通过真实浏览器回归 H5 商品到订单闭环，以及 Admin 商品、Banner、订单操作闭环。

## 4. H5 视觉系统：“晨露烘焙”

### 4.1 视觉语言

关键词：清透、轻盈、新鲜、自然、柔和、商品优先。

- 主背景：接近白色的雾绿/暖白，不使用大面积明显黄底。
- 主色：低饱和鼠尾草绿，用于主要按钮、选中态、链接和焦点环。
- 强调色：柔杏橙，仅用于价格、少量促销标签和关键提示。
- 辅助色：薄荷浅绿、晨雾蓝灰、浅桃粉，用于状态和插图背景。
- 文本：深墨绿灰代替纯黑；次级文本提高与背景的对比度。
- 视觉重量：使用 1px 柔和边框和短距离浅阴影，减少大面积重阴影。

### 4.2 Token

在 `styles/theme.css` 中统一定义：

- 颜色：canvas、surface、surface-muted、primary、primary-strong、accent、text、text-muted、border、danger、warning、success。
- 间距：4、8、12、16、20、24、32。
- 圆角：10（控件）、16（普通卡片）、22（重点卡片）、999（胶囊）。
- 阴影：card、floating、overlay 三级；普通列表默认优先边框而非阴影。
- 字体：系统无衬线为正文；仅 hero/大标题允许有限使用中文衬线，商品名和表单标题统一无衬线。
- 尺寸：页面最大宽度 560px；默认水平 gutter 16px；触控目标最小 44px。

同步覆盖 Vant 变量，确保 ActionSheet、Toast、Button、Stepper 等继承统一风格。

### 4.3 页面骨架

所有 H5 页面遵循：

```text
StorePage
├── PageHeader（可选返回、eyebrow、标题、说明、右侧动作）
├── PageContent
│   ├── Section/Card
│   └── StatePanel（loading/error/empty）
└── FixedAction / StoreTabbar（按页面需要）
```

规则：

- 页面根节点统一 `width: min(100%, 560px)`、居中和安全区。
- 带底部导航的页面统一预留导航高度；带固定结算条的页面额外预留操作条高度。
- 页面标题不再每页自定义字号、margin 和颜色。
- 卡片不通过随意阴影区分层级；主要依靠背景、边框、间距和标题。
- 所有按钮、输入框、textarea、number、radio、stepper 统一高度、圆角和 focus 样式。

### 4.4 关键页面

#### 首页

- 顺序保持 Banner → 品牌 hero → 分类 → 商品 → 未来内容位 → 底部导航。
- Banner 使用固定比例和统一文本渐变遮罩，避免图片本身可读性不可控。
- hero 缩减装饰体量，不再与 Banner 争夺主视觉；突出“当日现做”的品牌承诺。
- 分类为轻量横向胶囊，首字标识统一尺寸。
- 商品卡使用一致图片比例、两行商品名/简介截断和固定价格区，保证双列底线对齐。

#### 分类与商品详情

- 分类页使用统一 header 与搜索/结果信息条。
- 商品详情图库、悬浮摘要和富文本区使用连续的内容节奏；返回按钮与安全区固定。
- SKU ActionSheet 顶部、选项、数量和提交操作形成明确分区；不可售状态有文字说明。

#### 购物车与结算

- 购物车行使用稳定的图片、信息和数量操作三列结构；替换突兀的浏览器原生 number 外观。
- 固定结算条与底部导航不重叠，金额和主按钮层级明确。
- 结算页将商品、履约、联系人、地址/取货时间、备注拆成统一表单卡片；错误信息靠近对应区域。
- 不完整表单和提交中状态必须清晰，不能只靠颜色变化。

#### 订单、地址与个人中心

- 订单列表与详情统一状态胶囊、金额、时间和快照信息层级。
- 地址列表、编辑表单和默认标记统一卡片规则。
- 个人中心增加清晰的账户卡和功能入口，但不虚构未实现数据。
- 登录页与商城风格一致，并保留开发提示的次级视觉层。

## 5. Admin 视觉系统：“店长小助手”

### 5.1 视觉语言

关键词：轻二次元、温柔、可爱但专业、信息高效。

- 主色：低饱和薰衣草紫，不使用高饱和电竞紫。
- 点缀：樱花粉、薄荷绿、奶油黄，只用于状态、贴纸和局部引导。
- 背景：柔白与极浅紫灰，数据面板保持高对比白色。
- 二次元元素：品牌头像、星芒、胶带/贴纸、柔和几何角色和插画空状态。
- 二次元元素集中在侧栏、dashboard、页面头和空状态；表格、筛选和复杂表单保持克制。

### 5.2 Token 与 Element Plus 覆盖

在 `styles/theme.css` 中建立：

- admin canvas、surface、surface-soft、sidebar、primary、pink、mint、yellow、text、muted、border。
- 统一 radius、shadow、content max-width 和页面 gutter。
- 覆盖 Element Plus 的 primary、success、warning、danger、border、fill、text、radius 和 box-shadow 变量。
- 统一 `.el-card`、`.el-table`、`.el-form-item`、`.el-input`、`.el-select`、`.el-dialog`、`.el-drawer`、`.el-pagination` 的视觉密度，保留标准交互行为。

### 5.3 应用布局

桌面布局：

```text
AdminShell
├── Sidebar（品牌、分组导航、轻装饰、版本）
└── Main
    ├── Topbar（面包屑/页面标题、用户区）
    └── ContentCanvas（统一宽度、gutter、滚动）
```

规则：

- 侧栏宽度约 248px，导航包含线性图标、文字、active 胶囊和分组。
- 顶部栏高度约 68px，保持 sticky；不重复业务页面的大标题。
- 内容区最大宽度约 1600px，超宽屏居中；复杂表格可占满可用宽度。
- 小于 1024px 显示明确的桌面建议，同时允许关键内容横向滚动，不直接隐藏主功能。

### 5.4 统一页面结构

所有业务页使用：

```text
AdminPage
├── PageHeader（eyebrow、标题、说明、主操作、轻装饰）
├── FilterCard / Toolbar（可选）
├── Feedback（错误/提示）
└── DataPanel / FormSections
    └── Pagination / StickyActions
```

通用规则：

- Banner、订单、商品、分类不再各自实现不同的渐变头。
- 页面主操作固定出现在 PageHeader 右侧。
- 表格面板统一边框、圆角、表头背景、行 hover 和空状态。
- 筛选区统一 label、控件高度、换行和查询/重置按钮位置。
- 弹窗、抽屉统一标题、footer 间距和危险操作表达。

### 5.5 关键页面

#### Dashboard

- 移除“Task 占位”开发文案，改为店长欢迎区、功能快捷入口和流程提示。
- 不展示伪造 KPI；在真实统计 API 完成前使用“入口卡片”而非数字卡片。
- 加入轻量品牌角色/烘焙贴纸，不引入动画干扰。

#### 商品与编辑器

- 商品列表采用统一 PageHeader + DataPanel。
- 编辑页将基础信息、媒体、详情、SKU、发布设置拆为明确分区，形成稳定的纵向任务流。
- 保存操作采用可见的 sticky action bar，上传中、保存中、冲突和重新加载状态保持清晰。
- SKU 表格允许必要横向滚动，不压缩关键输入控件。

#### 分类、Banner、订单

- 分类与 Banner 列表共享数据面板和状态开关样式。
- Banner 图片、标题、目标与状态形成清晰行结构。
- 订单筛选区优先保证单行效率，窄屏时按规则换行。
- 订单详情抽屉强化快照分组和状态操作区；取消不回补库存提示保持醒目。

#### 登录与空状态

- 登录页使用左右分栏：表单为主，轻角色插图为辅；窄屏仅显示表单。
- 空状态使用统一插画/贴纸语言和明确下一步操作，禁止只显示大块空白。

## 6. 组件与文件边界

遵守项目既有前端六模块与函数式约束。

### H5 建议新增/统一

- `styles/theme.css`：token、reset、Vant 覆盖、全局 utility。
- `components/layout/StorePage.vue`：页面宽度和安全区。
- `components/layout/StorePageHeader.vue`：统一标题结构。
- `components/layout/StoreSection.vue`：区块标题与内容。
- `components/feedback/StoreStatePanel.vue`：loading/error/empty。
- 既有 `ProductCard`、`StoreTabbar`、`SkuPicker` 继续作为领域组件，不访问新增 API。

### Admin 建议新增/统一

- `styles/theme.css`：token、reset、Element Plus 覆盖。
- `components/layout/AdminPage.vue`。
- `components/layout/AdminPageHeader.vue`。
- `components/layout/AdminDataPanel.vue`。
- `components/feedback/AdminEmptyState.vue`。
- 导航配置与图标信息集中到 `config/navigation.ts`，布局只渲染。

不得把业务请求迁入展示组件；不得复制共享 DTO；不得引入平行业务状态。

## 7. 响应式与可访问性

### H5

- 支持 360–560px 主要宽度，并兼容更窄设备的安全降级。
- 触控目标至少 44×44px；固定底栏使用 safe-area inset。
- 文本在系统字体放大后允许换行，不用固定高度截断关键操作。
- 图片有 alt；状态不能只靠颜色；focus-visible 清晰。

### Admin

- 主要支持 1024–1920px。
- 表格在内容不足时不无限拉伸，在列较多时使用横向滚动。
- 重要操作保留文字标签，不使用只有图标的不可识别按钮。
- 色彩对比满足正常阅读；状态同时使用文字与颜色/图标。

## 8. 数据流与错误处理

- 所有 API、hooks、store、router 和事件名保持现状。
- 视觉组件只消费 props/slots 并 emit 事件。
- loading、error、empty、disabled、uploading、saving、conflict 等状态全部保留并统一表现。
- 错误提示不被装饰遮盖；弹窗和抽屉关闭行为不改变。
- 固定操作条不能遮挡最后一个表单项或底部导航。

## 9. 验证与验收

### 自动检查

- 更新因 DOM 结构变化而受影响的组件测试，但不放宽业务断言。
- 分别运行 H5/Admin 定向测试、typecheck、lint、build 和格式检查。

### 真实浏览器验收

H5 至少驱动：

1. 首页 Banner、分类、商品卡和底部导航。
2. 商品详情 → SKU → 登录 redirect → 加购。
3. 购物车数量/删除 → 结算 → 自提订单 → 订单详情/列表。
4. 地址、个人中心和登录页的空态/表单态。
5. 360px、430px、560px 三种宽度，无横向溢出或固定栏遮挡。

Admin 至少驱动：

1. 登录 → dashboard → 分类/商品/Banner/订单导航。
2. 商品列表、新建、编辑、上传、SKU 横向内容和 sticky 保存。
3. Banner 列表/弹窗与订单筛选/详情抽屉。
4. 1024px、1440px、1920px 三种宽度，无内容错位；必要表格可以受控横向滚动。

### 验收标准

- 两端页面使用统一 token 和页面骨架，不再出现同层级页面使用明显不同的 margin、radius 和 shadow。
- H5 呈现清透白绿主调，商品与操作优先，固定操作区不互相遮挡。
- Admin 能明确识别为轻二次元品牌后台，同时表格、筛选和表单效率不降低。
- 所有已验收业务流程保持可用；视觉重构不新增 API 请求、不改变 payload、不改变状态机。

## 10. 实施策略

该任务预计修改超过 5 个主要文件，采用完整流程：

1. 建立视觉基础与共享组件。
2. 先迁移 H5 核心交易流程，再覆盖辅助页面。
3. 迁移 Admin 壳层与通用页面结构，再覆盖业务页面。
4. 定向验证每一批，最后进行两端真实浏览器验收与一轮相应级别审查。
